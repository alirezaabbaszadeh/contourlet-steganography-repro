\section{Self-Describing and Failure-Aware Transport}

The header is treated as a first-class part of the communication system rather than an external assumption. It stores:

\begin{itemize}[leftmargin=*]
  \item a fixed magic identifier and format version;
  \item the C0--C3 method identifier and ECC mode;
  \item secret width and height;
  \item Base and Detail bit depths;
  \item Base and Detail codeword counts and padding;
  \item total payload length;
  \item interleaver and scrambler identifiers;
  \item payload CRC32;
  \item SHA-256 digest of the canonical configuration.
\end{itemize}

The raw 127-byte header includes its own CRC32 and is then encoded as RS(255,127). It can therefore correct up to 64 symbol errors before structural and integrity checks are applied.

Randomisation is deterministic and context-bound. Layer seed material includes a domain separator, a 128-bit master seed, the length and content of the image-pair identifier, the method identifier, and the layer name. Separate purpose digests generate scrambling and interleaving streams. Length-prefixing avoids ambiguity that could arise from naive concatenation.

The decoder records more than a binary success value. Its metadata includes corrected-symbol counts for every Base and Detail codeword and the SHA-256 value of each reconstructed permutation. Failures record the stage, layer, and codeword index. These records enable future analysis of error-free codewords, corrected codewords, correction margins, and the order in which Base and Detail cross their decoding thresholds.

Critically, the system does not convert uncertain bytes into a plausible secret image. If Reed--Solomon decoding or payload CRC validation fails, the recovered image remains absent. This rule can produce harsher outcomes than displaying a partially corrupted image, but it prevents invalid bits from being credited as successful recovery.

\section{Audited Transform Interpretation}

The final research path uses an explicit PDFB interpretation with 9--7 pyramid filters, PKVA directional filtering, and four multiscale levels. Independent coordinates are exposed from the P3+P4 range.

The transform adapter verifies more than the availability of a function named \code{pdfbdec}. It checks that required functions resolve inside the locked toolbox tree, preventing a shadowed or incompatible function from another path from changing the experiment. It records the toolbox-tree hash, bridge-source hash, filter configuration, level schedule, coordinate structure, band shapes, and capacities.

Quantitative transform gates cover reconstruction error, coefficient self-gain, cross-talk, off-target energy, available capacity, dense-sign writing, and write--read consistency. The selected coordinate pool provides enough capacity for the full 222,360-bit stream.

The profile nevertheless remains an independently specified interpretation. It is not labelled as the undisclosed MATLAB configuration of the source authors. This boundary is central to the paper: a transparent independent reconstruction can be scientifically valuable without being misrepresented as an exact reproduction.

The design supports four direct contrasts:

\begin{align}
A_{\mathrm{main}} &= \frac{(C1-C0)+(C3-C2)}{2},\\
D_{\mathrm{main}} &= \frac{(C2-C0)+(C3-C1)}{2},\\
A\times D &= C3-C2-C1+C0,\\
\mathrm{Combined} &= C3-C0.
\end{align}

The locked dataset contains four traceability pairs. Each method is embedded once per pair, yielding 16 embedding objects. The mandatory evaluation contains clean output and three medium channel families:

\begin{itemize}[leftmargin=*]
  \item JPEG quality 70;
  \item Gaussian noise variance 10;
  \item salt-and-pepper density 0.03.
\end{itemize}

Predeclared trigger rules activate bounded hard checks at JPEG quality 50, Gaussian variance 15, and salt-and-pepper density 0.05. The final schedule contains 64 mandatory rows and 24 conditional hard rows, for 88 total evaluations.

All attacks operate at explicit uint8 boundaries and use fixed seeds where stochastic behaviour is involved. The same pair, payload, quality constraint, transform profile, and channel realisation are used across methods.

The statistical framework supports paired bootstrap intervals, sign-flip tests, Wilcoxon tests, rank-biserial effect sizes, and Holm correction. It first aggregates repeated seeds within each pair, avoiding pseudoreplication. Because the final experiment contains only four fixed traceability cases, however, the reported inference remains descriptive and case-bounded rather than population-level.

\section{Metrics and Validity Rules}

The evaluation separates visual quality, raw transport damage, layer recovery, and valid complete recovery. Recorded fields include:

\begin{itemize}[leftmargin=*]
  \item cover--stego MSE, PSNR, and SSIM;
  \item raw BER over the complete transport;
  \item Base BER and Detail BER;
  \item header validity and payload-CRC validity;
  \item secret MSE, PSNR, and SSIM when a valid secret exists;
  \item selected embedding strength;
  \item embedding, attack, and extraction time;
  \item peak worker memory;
  \item failure count and immutable object identifiers.
\end{itemize}

The primary conservative measure is the effective unrecovered bit rate, \(\eur\). A value of zero means that the complete protected payload was validly recovered. A value of one means that the contract could not assign valid recovery credit to any scheduled payload bit. This metric prevents failed CRC or missing output from disappearing from a conditional BER average.

Raw BER and layer BER remain important diagnostic measures. They can reveal gradual improvements that do not yet cross the complete-payload validity threshold. Corrected-symbol telemetry offers an additional view of distance to failure.

\section{Execution and Provenance}

Scientific execution is treated as part of the experimental method. Each embedding and channel evaluation is represented by a content-addressed object. Object identity is determined by the inputs and outcome-determining configuration. Completed objects can be reused only after validating schemas, required files, and SHA-256 digests.

Writes are atomic, preventing a partially written directory from being interpreted as a completed result. Invalid cache objects are quarantined rather than silently overwritten. The run plan is bounded: 16 embedding objects, 48 core channel evaluations, and at most 24 conditional hard checks.

The final runtime gate terminates a real worker with SIGKILL, verifies that completed objects remain unchanged, resumes unfinished work, validates all expected objects, and exports a self-verifying archive. Monitoring is separate from the scientific worker: it reads durable state and operating-system counters but cannot alter content-addressed research objects.

This infrastructure matters because a negative result is only meaningful when failure cannot be attributed to an interrupted process, a stale cache, mixed configuration, toolbox shadowing, or silently changed input.
